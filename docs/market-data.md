# 市场数据与上线核对

## 游客直接使用

快讯、涨停复盘、条件筛选、CSV 导出和本机自选均无需账户或行情密钥。采集、缓存和故障切换由服务器或 GitHub Actions 完成，浏览器读取本站接口或公开快照，不要求访客处理上游跨域问题。

页面按当前设计隐藏提供方标签，仍保留原文链接、真实发布时间、交易日期、获取时间及历史快照状态；来源元数据保存在内部数据结构和本文中。

## 数据来源与统计口径

| 栏目 | 上游接口 | 数据与用途 |
| --- | --- | --- |
| 快讯主源 | `https://np-weblist.eastmoney.com/comm/web/getFastNewsList` | 东方财富标题、摘要、发布时间、原文链接 |
| 快讯备用一 | `https://newsnow.busiyi.world/api/s?id=cls-telegraph` | 财联社电报，发布时间取条目 `pubDate` |
| 快讯备用二 | `https://newsnow.busiyi.world/api/s?id=wallstreetcn-quick` | 华尔街见闻快讯，发布时间取条目 `extra.date` |
| 涨停复盘 | `https://push2ex.eastmoney.com/getTopicZTPool` | 实际股池明细、首板/连板、最高连板、行业与连板分布 |

以上为公开匿名入口，不需要个人 API key，但可能限流、缓存或变更，不是有可用性保证的付费行情订阅。东方财富接口参数里的 `ut` 是公开客户端标识，不是个人凭据。NewsNow 通过后台访问，不假设其 API 支持浏览器跨域。

### 新闻时间与备用切换

东方财富请求保留必填的空参数 `sortEnd=`。其 `showTime` 按北京时间解析；条目清洗、去重后按真实时间排序，最多40条。

主源请求失败、格式错误或没有有效条目时，依次尝试 NewsNow 的两个财经快讯源。主源最长6.5秒，备用每源最长4秒且共用8秒预算，超时涵盖响应正文解析；新闻与涨停查询并行。

NewsNow 的条目时间为毫秒时间戳，适配器也支持带时区的 ISO 日期。`updatedTime` 只是缓存元数据，不能用作新闻发布时间；无时间、未来时间、错误状态、无效条目或最新条目超过24小时的备用响应会被拒绝，以便继续切换或保留已有成功数据。普通 NewsNow 响应可能使用缓存，不通过 `latest=true` 强制刷新。其热榜缺少条目发布时间，不混入按时间排列的快讯。

链接只接受对应来源允许的 HTTPS 域名；备用源同时拒绝带用户名、密码、异常端口及恶意协议的链接。正文使用标题、短摘要与原文入口，不将热榜名次或缓存获取时间包装成金融实时指标。

### 涨停股池与交易日期

股池统计以接口实际收录为准，不代表全市场涨停数量。本次真实股池包含科创板及北交所股票，例如2026年10月16日的司南导航（688592）、晟楠科技（920006）与捷众科技（920690）。因此不再使用“排除科创板”的旧口径，也不据代码前缀自行删除有效记录。北交所股票详情链接使用 `bj` 市场前缀，不能仅凭东方财富市场编号将其归为深圳。

- `p` 为千分之一元，展示前除以1000；`fund` 为元；`zdp` 已是百分数。
- `lbc` 为连续涨停板数。首板加连板家数等于当前股池记录数；声明的总数与返回记录数不符时拒绝不完整数据。
- `fbt` 补足6位后显示北京时间；无有效时间显示“—”。
- 行业为上游分类，不代表涨停原因。股池不能证明净流入、情绪分数、全市场炸板率或晋级率，因此不生成这些指标。
- 空池、休市或尚未发布不解释为“0家涨停”。默认模式探查最近16个自然日内的工作日，保留实际最近可用交易日期。
- `qdate` 表示来源最近交易日，历史查询中也可能携带最新日期。请求日期晚于 `qdate` 时，上游可能返回最近一日的旧池：最新模式保留该真实日期；指定日期模式显示所选日期暂无已发布股池，不把旧池重标为所选日。查询更早历史日期时，不以最新 `qdate` 覆盖请求的历史日期。

## 两种部署模式

### Cloudflare/Vinext

`worker/index.ts` 的同源 `/api/market` 聚合新闻和股池。单实例60秒缓存、合并并发刷新，失败后15秒可重试；缓存最多32项，不需要新增数据库迁移。

页面每60秒检查更新，隐藏页面暂停轮询，重新可见时刷新。近30天日期查询仅在此模式提供。新闻和股池分别保留上次成功结果，失败不刷新成功时间，也不把另一交易日的缓存挂到新日期下；股池新响应为空且已有同口径成功数据时，保留旧池并标记历史快照。

### GitHub Pages

静态站通过两条工作流自动准备数据：

1. `Deploy to GitHub Pages` 恢复 `market-data` 分支的最近快照，再执行 `node scripts/update-market-data.mjs --require-data`。首次部署若任一栏目没有可用结果则停止发布；已保留的有效历史快照可以带明确状态随构建发布。来源明确返回的空股池也是有效状态，不伪造股票填充。
2. `.github/workflows/update-market.yml` 在相关文件推送到 `main` 时自动初始化或更新数据，并按 UTC cron `2-57/5 * * * *`（每小时02、07、12至57分）约每5分钟更新。手动 `workflow_dispatch` 仅作为维护恢复入口，不是首次使用的必需步骤。

行情更新只写独立 `market-data` 分支中的 `market.json` 和 `.gitignore`，从空索引构造发布树，不复制应用代码、工作区文件或凭据。官网部署只读取该分支，避免与定时更新发生多写入方竞争。

浏览器默认读取：

`https://raw.githubusercontent.com/MISSyouy7/whitebeard-research/market-data/market.json`

可用 `NEXT_PUBLIC_MARKET_SNAPSHOT_URL` 指定其他匿名可读的公开 HTTPS 快照。分支读取遇到网络、HTTP 或格式问题时，浏览器尝试构建内 `data/market.json`；某栏目不可用时独立保留已有有效数据。两者都失败时保留本次浏览已获取的历史数据及原时间，没有成功数据则显示连接状态与重试入口。

浏览器每分钟检查快照。GitHub Actions 调度和 raw 文件缓存可能延迟，页面使用“定时更新”，不承诺秒级实时；静态快照超过20分钟会显示历史快照状态。页面刷新时间不代替采集时间。采集失败仍发布带原成功时间的回退数据，同时让工作流报告更新失败，便于维护者发现问题。

仓库需允许 `contents: write`，定时工作流需存在于默认分支，快照地址须可匿名读取。GitHub 可能暂停长期不活跃仓库的定时任务，恢复时可手动触发同一工作流。

## 本地实网检查

```bash
pnpm market:update
node scripts/update-market-data.mjs --require-data
```

本云环境使用 Node.js 24，采集脚本访问允许的外部接口时需启用环境代理：

```bash
NODE_USE_ENV_PROXY=1 pnpm market:update
```

该设置使用环境已有代理，不写入个人密钥，也不绕过域名访问规则。普通本地环境可按自身网络条件使用默认命令。`vinext dev` 的 `/api/market` 在 workerd 中运行；本云容器 workerd 的外网 DNS 仍失败，Node 采集成功不等于本地 Worker 接口已连通。当前实网验证使用 Node 采集脚本生成的真实静态快照，生产 Worker 需单独检查。

## 验证记录与发布检查

2026年10月18日已通过 Node 采集脚本读取真实东方财富响应：快讯40条，2026年10月16日涨停股池61只，其中首板54只、连板7只、最高11板。实测10月17日和18日的上游请求会返回10月16日同一股池；10月15日历史请求则返回36只，同时仍携带最新 `qdate=20261016`。这些数字用于核对日期处理，不是固定展示数据。

NewsNow 域名在本环境的代理连接阶段仍返回403，不能据此判定其站点失效，也不宣称备用源实网验收通过。备用模块11项契约测试覆盖两来源、真实时间、非法链接、去重、过期缓存、故障切换，以及请求和 JSON 解析超时。单元与浏览器测试的合成数据仅用于测试，不写入公开行情快照。

每次发布后需检查：

1. 官网部署与行情更新工作流均完成，公开快照包含有效栏目或明确历史状态。
2. 生产域名显示真实新闻发布时间及交易日期；周末可展示最近交易日，不能只凭 HTTP 200 判断正确。
3. 抽查原文链接、沪深北股票代码与详情页、价格及封单资金单位，并核对图表与表格统计一致。
4. 首板、连板、行业和关键词筛选、CSV 导出、本机自选在手机端可直接使用。
