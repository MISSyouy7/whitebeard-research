# 产业周刊

研究区接入两个仍持续维护的中文刊物，每个保留最近四期：

- [科技爱好者周刊](https://github.com/ruanyf/weekly)：从 README 中读取正式期刊目录，不采集投稿 issue；主题涉及科技、产品与商业观察。
- [AI 论文周报](https://github.com/careywyr/AI-Weekly-Paper)：读取年度目录中的每周 Markdown，提供中文论文解读及论文链接。它是技术前沿阅读材料，不是上市公司研报。

卡片统一进入站内阅读页。周刊阅读页提供路见编写的阅读框架、产业观察问题和从本期提取的篇目标题索引，明确标注为“周刊导读”，不搬运第三方全文或图片，也不将第三方作品署名为路见原创。具体论文/项目资料为可选链接，原刊入口收在页尾。卡片的“更新”日期来自对应 Markdown 文件的最新 Git 提交，AI 周报标题另保留原始覆盖周期。

阅读页沿用手机目录、阅读进度和带筛选状态的返回入口。路径由刊物身份确定，例如 `/research/weekly-tech-415/`、`/research/weekly-ai-2026-1012-1016/`；访问阅读页不需要浏览器连接 GitHub。采集后的目录元数据随快照保存；旧版快照仍能生成基础导读，避免采集失败时卡片外跳。

`A股市场复盘` 已从研究卡片、搜索、首页推荐及公开文章路由中移除。原 Markdown 保留在仓库作历史档案；首页涨停股池功能继续使用。

## 更新

```bash
pnpm periodicals:update
pnpm build:pages
```

云环境通过现有代理运行采集时使用 `NODE_USE_ENV_PROXY=1`。GitHub Actions 使用自身只读 `github.token` 访问 GitHub API，无需访客配置密钥；凭据不会进入快照或浏览器。项目无需运行这些上游仓库中的程序。

`Deploy to GitHub Pages` 在推送、手动执行和北京时间每天 08:17（UTC `17 0 * * *`）运行。部署前先采集，再静态构建，因此无需用户手动编辑文章。GitHub 计划任务可能延迟；是否出现新刊取决于作者是否发布，不会将检查时间当作文章更新日期。

`public/data/periodicals.json` 同时作为构建输入和公开快照。每天采集前读取官网上次发布的同名快照，按刊物恢复较新的成功数据；若个别源失败，保留该刊物的内容和原获取时间，页面注明“暂未刷新”。其他源照常更新。首次部署任一刊物没有可用内容则停止发布。网络中断时仍可用仓库内已有快照构建。若官网域名变化，同时更新 `scripts/update-periodicals.mjs` 中的恢复地址。

验证：`node --test tests/periodicals.test.mjs` 覆盖目录解析、跨年周报、恶意链接、真实日期约束、独立故障与线上快照恢复。不要把仓库推送时间或自动检查时间当作期刊发布日期。
